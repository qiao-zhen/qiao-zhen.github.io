桥桥工作台 · 多端数据同步实现原理

手机 / 电脑 / iPad 数据怎么互通的？一份给自己的技术备忘录

1一句话原理

工作台本身是个纯前端网页（HTML + JS + localStorage），没有自己的服务器。它把 GitHub 仓库当成一个"云端数据库"：你的每条数据都存成浏览器里的 localStorage，改动了就自动上传到 GitHub 的一个 userData.json 文件；换设备打开时，再从 GitHub 把这个文件下载下来填进本地。

核心公式 本机 localStorage ⇄ GitHub 的 userData.json（直连 API，不经过任何中间服务器）

  • 本机存储：16 个用户数据 key（待办、台账、笔记、打卡…）存浏览器 localStorage，关掉页面数据还在。
  • 云端存储：GitHub 仓库 qiao-zhen/qiao-zhen.github.io 里的 userData.json，就是所有设备的"公共备份"。
  • 传输：网页用浏览器 fetch 直连 api.github.com（PUT 写 / GET 读），不经过 Cloudflare 等中间 Worker（国内连不上）。
  • 身份：一个 GitHub fine-grained Token（只授权该仓库 Contents 读写），存在你本机浏览器，不上传、不写进任何文件。

3写入（同步到云端）怎么实现

每次你在页面里新增 / 修改 / 删除任意模块，底层拦截了浏览器的保存动作：

// 拦截 Storage.setItem，自动触发上传（防抖 0.7 秒） Storage.prototype.setItem = function(k, v){ origSetItem.apply(this, arguments); if (SYNC_KEYS.indexOf(k) >= 0 && getGithubToken()) { scheduleCloudPush(); // 0.7s 内没再改动才真正发请求 } };

真正上传时用 PUT 把整个 userData.json 写回 GitHub：

PUT https://api.github.com/repos/qiao-zhen/qiao-zhen.github.io/contents/userData.json Headers: Authorization: Bearer <你的token> Body: { "message": "auto sync", "content": <base64(UTF-8 编码的 JSON)>, "sha": <先 GET 拿到的文件 sha，防止冲突> }
  • 防抖 0.7 秒：狂敲键盘不会刷接口，停手才传。
  • 先取 sha 再写：GitHub 要求带旧版本号，避免两人同时改把对方覆盖（冲突时返回 409，会重试）。
  • Token 输入即存：顶栏「☁ 同步」填一次，关掉再开还在。
✅ 所以"同步到云端"是全自动的——你正常用页面，数据就一直在往 GitHub 跑，不用点按钮。

4读取（拉取云端数据）怎么实现

读取分两种模式，由 force 参数控制：

场景触发行为
自动拉取每次打开页面force=false → 只填空缺，本地已有数据绝不覆盖
手动拉取点「拉取云端数据」force=true → 整份覆盖本地

读哪份数据（关键修复点）：曾经"拉取"优先读 GitHub Pages 静态文件（qiao-zhen.github.io/userData.json），那份有 CDN 缓存 + 部署延迟，永远是旧版——导致你删了待办又被旧版拉回来。

⚠️ 现已改为：拉取优先读 API（和"写入"同一个地址，数据最新），GitHub Pages 只作无 Token 时的兜底，且兜底也强制"只填空缺"。从此读写同源，删了就不会复活。

6踩过的坑 & 已修复

  • 读写不同源（已修）：拉取读 Pages 旧版 → 已改为读 API 同源。
  • 示例数据覆盖真实（已修）：ensureFallbackData 原本会把内置示例强行写回，冲掉你的真实数据 → 改为只填 localStorage 里为 null 的键，绝不覆盖已有数据。
  • Token 不持久（已修）：原本只在拉取时存 → 改为输入框 oninput 实时存本地。
  • .nojekyll 必须空文件（铁律）：带任何内容会让 GitHub Pages 构建报错、网站一直停在旧版。必须 0 字节。
  • 推送不同步 userData.json：刷新 AI 内容只推 data.json；你的真实同步数据在 userData.json，绝不拿本地副本覆盖云端。

7你能做什么 / 不能做什么

  • ✅ 多设备（手机/电脑/iPad）共用同一份数据
  • ✅ 断网时本地照常用，联网后自动补齐
  • ✅ 手动点「同步到云端 / 拉取云端数据」可强制收发
  • ❌ 没有"实时秒同步"：靠保存触发 + 0.7s 防抖，不是 WebSocket 长连接
  • ❌ 多人同时狂改同一模块可能冲突（GitHub 409 重试，偶尔需手动再拉一次）
  • ❌ 别在待办 / 台账里写密码、银行卡号等敏感信息（云端是公开仓库文件）
